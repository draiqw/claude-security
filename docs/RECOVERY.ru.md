# После перезагрузки, обрыва связи или переустановки

## Проверка одной командой

В терминале Mac запустите `claude-route-check`. Проверка ничего не устанавливает, не отправляет сообщений модели и не печатает токены. Код возврата 0 означает, что проверки прошли. Проверяется полная установка всех трёх режимов: если вы сознательно не ставили удалённый Chrome, соответствующий FAIL не означает, что модель или обычный браузер сломались. `CONNECT 200 → API 401` ожидаем: тест сознательно обращается без авторизации. Для входа проверьте отдельно `claude auth status`, для MCP — `claude mcp list`.

Обычная команда `claude` остаётся нативной: никакого alias, смены текущей папки или обязательного диагностического запроса при запуске. Если хотите не начинать работу после обнаруженной неполадки, используйте `claude-route-check && claude`. Это предварительная проверка, не firewall и не обещание о поведении всех дочерних процессов.

## Что происходит само, что сделать вам

| Событие | Что ожидается | Что сделать |
|---|---|---|
| Закрыли Терминал, вышли из чата | SSH-туннель API живёт под launchd, независимо от окна | Открыть Терминал и запустить `claude`; старый чат при необходимости — `claude -c` в папке проекта |
| Перезагрузили Mac или вышли из пользователя | До входа пользователя его LaunchAgent не работает. После входа он заново запускает SSH | Разблокировать Mac/Keychain, дождаться сети и проверить `claude-route-check`. Если требуется VPN для SSH, включить VPN |
| Сон, смена Wi-Fi, VPN или падение SSH | KeepAlive запускает завершившийся процесс снова; ServerAlive обнаруживает зависший канал. Это не мгновенно | При восстановленной сети подождать; затем `launchctl kickstart -k "gui/$(id -u)/local.claude.proxy"`. Активный запрос может потребоваться повторить |
| Закрыли локальный Chrome | Его профиль и cookies остаются на Mac | `claude-web` |
| Закрыли Screen Sharing; оборвался VNC-туннель | Chrome на VPS обычно продолжает работать. Окно на Mac автоматически не открывается | `claude-web-vps` — повторно использует живой туннель или открывает новый |
| Перезагрузился VPS | SSH и Tinyproxy стартуют как системные службы. После первой настройки пароля `chrome-vps.service` тоже включён при загрузке | Дождаться SSH и `claude-route-check`, затем `claude-web-vps`. Профиль сохраняется на диске VPS; это не бэкап |
| Сбой процесса службы Chrome на VPS | systemd повторяет запуск при ошибочном завершении основного процесса. Нормальный выход из Chrome не считается сбоем | Если Chrome закрыт штатно, снова выполнить `claude-web-vps`. Если служба многократно падает, проверить журнал |
| Запустили `claude-web-vps --stop` | Останавливаются служба и туннель просмотра, но профиль не удаляется. Зарегистрированный сервис снова запустится при загрузке VPS | Для постоянного отключения автозапуска: `ssh my-germany-server 'systemctl disable --now chrome-vps'`. Следующий запуск лаунчера снова включит сервис |
| Обновили CLI без очистки настроек | Настройки обычно сохраняются | `claude --version`, `claude-route-check`; внутри `/status` проверить Proxy |
| Удалили `~/.claude` и поставили CLI с нуля | **Риск прямого подключения:** чистая установка не обязана наследовать прежний HTTPS_PROXY. Существование SSH-туннеля само по себе этого не исправляет | **До входа и первого чата** восстановить `settings.json` по разделу 5 [инструкции](SETUP.ru.md), затем выполнить `claude-route-check`. Пользовательские MCP, разрешения и логин восстанавливаются отдельно |
| Переустановили macOS, сменили пользователя | SSH-ключ, PATH, LaunchAgent, локальный профиль и лаунчеры могут отсутствовать | Пройти шаги 1–6 заново. Ключи восстанавливать только из собственного защищённого бэкапа. При чистой установке VPS пройти и шаг 7; не игнорировать изменение ключа сервера без сверки через провайдера |

## Обновление старой установки из репозитория

На Mac, **из вашего клона** (закоммитьте локальные изменения до обновления):

```sh
git pull --ff-only
mkdir -p ~/.local/bin
install -m 755 bin/claude-web bin/claude-web-vps bin/claude-route-check bin/claude-audit ~/.local/bin/
scp server/chrome-vps.service my-germany-server:claude-vps-updated.service
ssh my-germany-server 'install -m 644 ~/claude-vps-updated.service /etc/systemd/system/chrome-vps.service && systemctl daemon-reload && systemctl enable chrome-vps && rm ~/claude-vps-updated.service'
```

Серверная команда предполагает административный SSH-доступ, как и поставляемый VNC-лаунчер. Она не перезапускает уже работающий браузер. При обновлении с более ранних версий убедитесь, что `server/session` установлен по шагу 7 и применён LaunchAgent из шага 4. `claude-audit` — необязательная диагностика: создаёт подробные логи под `~/Library/Logs/claude-route-audit/`. Не публикуйте их. Это выборочное наблюдение, не полный сетевой дамп.

## Если проверка не прошла

1. `ssh -o BatchMode=yes my-germany-server true` — доступен ли сервер без ручного пароля? При сообщении о ключе SSH сверьте отпечаток с панелью провайдера. Не отключайте проверку ключей.
2. `launchctl print "gui/$(id -u)/local.claude.proxy"` и `lsof -nP -iTCP:18787 -sTCP:LISTEN` — загружен ли агент и принадлежит ли порт SSH? Если plist удалён или выгружен, повторите шаг 4. Если агент отключили вручную, сначала `launchctl enable "gui/$(id -u)/local.claude.proxy"`.
3. `ssh my-germany-server 'systemctl status tinyproxy chrome-vps --no-pager'`. Если VPS без дискового места, сломан профиль Chrome или истёк вход Claude, рестарт процесса это не исправит. При зависшем Chrome `systemctl restart chrome-vps` закроет открытый удалённый браузер; сначала сохраните свою работу.
4. Нет `claude-web` в новом терминале — проверьте `~/.local/bin` в PATH. Вышел срок сессии — `claude auth login --claudeai`; у двух браузерных профилей собственные сессии. После обновления Node/npm/uv могут исчезнуть локальные исполняемые файлы MCP — проверьте `/mcp`.

## Что проверено на действующей установке

Проверка в новой оболочке нашла команды. После намеренной остановки SSH-процесса launchd сам поднял новый процесс с другим PID; через него снова прошёл CONNECT до API. Затем отдельный авторизованный тест Claude получил ожидаемый ответ, оба браузерных лаунчера запустились, а на туннеле просмотра прочитан заголовок протокола RFB. Экран VPS сообщил 1920×1080. Службы SSH, Tinyproxy и удалённого Chrome зарегистрированы при загрузке. Затем выполнили реальную перезагрузку VPS: время загрузки изменилось, SSH, Tinyproxy и Chrome поднялись автоматически, VNC вернулся в 1920×1080. Сразу после старта VPS локальный порт Mac кратковременно был недоступен, затем `claude-route-check` прошёл без ручного старта туннеля. Это не тест перезапуска самого Mac. Для полного клиентского цикла: сохранить документы, перезагрузить Mac, войти в ту же учётную запись и запустить `claude-route-check` до ручного kickstart; записать результаты.
